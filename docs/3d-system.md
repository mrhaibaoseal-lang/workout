# 3D 角色、裝備、動作示範（正式版計畫）

最後更新：2026-11-22。原型在 `scripts/blender/`（說明見該資料夾 README），預覽在 `docs/art/blender/`。

## 使用者已決定
- 3D 用 **Blender 程序化建模**（Python 腳本產生，不手工雕刻），風格＝目前原型：卡通兩階著色＋黑描邊＋邊緣光、玩具公仔比例。
- **App 內即時 3D**（不是預先算好的影片）：示範動作時穿著自己目前的裝備；手機 iPhone 16 Plus 效能夠。
- **示範影片不放裝備特效**（fx 部位），避免干擾看動作；特效留給角色頁。
- 初始造型（身型以 2026-11-22 使用者選定的平直倒三角為準）：品牌橘貼身背心、深藍灰短褲、白鞋橘鞋底、深藍灰頭帶護腕；臉只有眼睛眉毛（蛋形頭，不加下巴零件）。
- 動作要準確、專業：手腳釘在地板／器材上，用 IK 解手肘膝蓋；器材照使用者自己的（見下）。
- 使用者的「多功能啞鈴椅＋高位下拉架」一體機已建模（`scripts/blender/moves/props_bench.py` 的 `build_bench`）：
  前端立柱＋頂部滑輪盒；**配重是立柱滑套上的兩顆啞鈴**，拉下時整組往上滑；可調靠背、頭枕、前端腳踝滾筒。

## 要做的量
- 動作：`CharacterMove` 約 60 個（訓練 ~40、熱身 8、伸展 10、休息頁 3）。動作庫 99 個動作會對應到這些示範。
  2D 版的角度資料在 `scripts/art/moves.js`，可當作 3D 的參考（側面角度 → 3D 要補左右寬度、手腳釘點）。
- 裝備：12 系列 × 8 部位 ＝ 96 件（`GearCatalog.swift`）。CLAUDE.md 的美術規定照樣適用（灰階認得出、同部位不撞形、越稀有越華麗）。
  目前做了 3D 測試版的系列：鈦甲（titan）、冰霜（frost，預覽 `docs/art/blender/frost.png`）、小豬（pig，預覽 `docs/art/blender/pig.png`；2026-11-24 使用者臨時提的新系列，還沒加進 `GearCatalog`／App）、英雄類四套夜巡者（night）、曙光（dawn）、符文戰神（rune）、星界魔導（astral）（2026-11-25 使用者定案，預覽 `docs/art/blender/heroes.png`），可逐部位混搭（`GEAR="head=titan,hands=titan"`）。

## 防穿模（動作多、造型多，小穿模可接受，但要系統化排除）
三層做法，越前面越省事：

**1. 設計規則（做裝備時就避開）**
- 硬殼裝備（盔甲片、護膝、手甲）只綁一根骨頭，放在肢段中段，**不跨關節**；關節附近只放小而圓的零件。
- 往身體外側凸的零件（側板、肩甲）有寬度上限：大腿側板離大腿中心線 ≤ 7 cm（手拿啞鈴會碰到）。
- **貼身衣服直接塗在身體上**（基本款背心就是這樣）：只有一層表面，不可能穿模，輪廓就是身體本身。
  使用者選定的身型＝身體本身的平直倒三角；另外做一層背心網格會變圓（放大 12% 時胸口鼓成球、腰收成沙漏）。
  邊界用頂點屬性（離邊界的距離）＋著色器判斷，邊緣是平滑的線；App 的即時著色器也要讀同一個屬性（`tank`）。
- 有厚度的衣服（短褲、緊身衣、外套）才另外做網格：沿用身體權重（Data Transfer），只比身體大 5～8%，
  衣服邊緣底下的身體塗成衣服色（透出來也看不到）。
- ~~身體軀幹（|x|<0.235）的手臂權重改給胸部~~（2026-11-24 取消：這個截斷就是肩膀凹陷鼓包的原因，背心是塗色不怕戳穿）。
- **身體變形（骨架與權重，2026-11-24）**：A 字靜止姿勢、鎖骨骨頭、平滑的關節權重漸變、保持體積、每格自動校正上臂滾轉。
  細節見 `scripts/blender/README.md` 和 BLENDER_BRIEF §6-1；檢查用 `deformcheck.py`（身體本身）和 `rigtest.py`（極限姿勢）。
  App 的 RealityKit 是線性蒙皮（沒有保持體積）：`LBS=1 deformcheck.py` 看的就是 App 會長的樣子；匯出的骨架多了 `clavicle.L/R`、靜止姿勢變 A 字，App 的 3D 測試要重新跑 `build_app.sh`。

**2. 動作層（做動作時就處理）**
- 接地修正：每一格算整個角色最低點，有東西沉到地板下就把整個人抬高（裝備比基本款厚時自動生效）。
- 背靠椅背或躺在椅子上的動作，示範時**隱藏背部裝備**（披風、背包），`hero_proto.py` 的清單。
- 手拿啞鈴的動作，手的軌跡要繞開大腿（深蹲蹲低時手往外）。

**3. 自動檢查（`scripts/blender/clipcheck.py`，每個動作 × 每個系列都跑）**
- 逐格（每 2 格）用三角形相交檢查：裝備 × 其他骨頭、身體 × 不相鄰骨頭、角色 × 器材（硬器材／軟墊分開）、沉入地板。
- 關節相連的骨頭本來就會重疊，不算；碰到軟墊（座墊、滾筒）是正常接觸，只列出不計入最嚴重的格。
- 只把最嚴重的格截圖給人看，不用逐格目視。修不掉的小穿模記在報告裡，可以接受。
- 動作 60 個 × 系列 12 個＝ 720 組，全部是電腦跑，不花 token；只有有問題的組才需要我看圖修。
- **增量批次**：`python scripts/blender/clipbatch.py`（`--moves`、`--series` 縮範圍，`--dry` 只列要跑的組，`--force` 全重跑，`-j` 並行數）。
  每組用輸入檔的雜湊當指紋，沒變就沿用上次結果：改一個動作批次檔只重跑那檔的動作 × 全系列，改 `gear_<系列>.py` 只重跑全動作 × 該系列，
  改共用檔（`hero_proto.py`、`moves3d.py`、`gear_util.py`、`clipcheck.py`、`moves/props_*.py`）才全部重跑。
  結果在 `out/clipcache/`（總表 `summary.json`）；草稿模式一組約 30～60 秒。
- 不跨系列混搭檢查（混搭組合太多）；混搭靠第 1 層的寬度上限避免互撞。
- 大腿內側互碰（`body:thigh.L × body:thigh.R`）是身體本身造成的，每個系列都一樣，不是裝備問題。
- 身體塗色（上衣畫在身體頂點屬性上）不能漏到腰以下：hero_proto 合併前檢查，z<0.95 有任何塗色屬性 >0 就報錯。
  用 `tee_parts` 的袖口畫滾邊要再 `min(..., hem)`（2026-11-24 小豬短褲露出小腿才發現）。
  只檢查皮膚面（材質 0）讀的屬性；短褲範圍的面塗下身花色（褲管反摺）是正常的。
- 短褲底下的身體從 z 0.72 起塗短褲色，會露出在褲管最下緣：短褲上的花色（反摺）要在身體那段也塗一份。
- 蛋形的背部裝備只有一點貼背，伏地挺身從側面看會像浮著：中間加一塊背墊填空隙。
- clipcheck 比對材質名只去掉 Blender 的 `.001`（以前用 rstrip 數字，`fr1`、`pg1` 被當成身體）。

## 階段
1. **技術驗證（先做，決定整條管線）**：把基本款角色＋一個動作放進 App，用 RealityKit 即時播放，上機確認：
   - 格式：USDZ（帶骨架動畫）。這裡的 Ubuntu Blender 4.0 沒有 USD 匯出；改在 GitHub Actions macOS runner 下載官方 Blender 匯出，
     或在這裡用 Python 3.11 + PyPI `bpy`。
   - 卡通著色：RealityKit `CustomMaterial`（Metal surface shader）做兩階明暗＋邊緣光。
   - 描邊：模型裡烘一層反向外殼（solidify），用 UnlitMaterial、剔除正面。
   - 裝備開關：每件裝備是獨立節點，依背包啟用／隱藏；動作片段（clip）切換。
   - 效能、IPA 大小、「減少動態效果」時的處理（停在關鍵姿勢）。
   **進度（2026-11-24，0.35.0 試做）**：`scripts/blender/build_app.sh` → `Workout/Hero3D/`；App「設定 → 3D 測試」。
   - 匯出：這台 Windows 的 Blender 5.2 有 USD 匯出，直接出 USDZ（不用 macOS runner）。`EXPORT=frost,titan` 建出基本款＋各系列的剛性部位，
     `export_app.py` 依「零件 × 材質」拆成獨立網格（名稱 `<部位>_<系列>__<材質>`），描邊外殼烘成 `__ol`，背心塗色欄位放 UV。
   - 著色：`Toon.metal`（CustomMaterial、unlit 自己算光），材質參數讀 `hero3d.json`，不靠 USD 材質。
   - 動作：`hero3d_clip_<動作>.json`（每格每根骨頭的局部變換）由 App 寫進 `jointTransforms`，換動作不用另一份模型；
     接地高度依穿著的零件即時算（每個零件每格的最低點）。USD 內建動畫也留著做對照。
   - 已知未做：上衣／下身（塗在身體上的衣服、長褲網格）還不能在 App 裡換；發光沒有泛光（bloom）。

     - 著色器描邊：每個本體 clone 一個帶同一副骨架的實體，網格用本體的卡通材質 part（同位置頂點的法線取平均），

   **上衣／下身換裝（設計定案 2026-11-25，還沒做）**：
   - 現況：上衣、下身只在 hero_proto 建模時依 `G['top']`／`G['bottom']` 決定，`EXPORT=` 只帶剛性部位，App 換不了。
     塗色＝身體頂點屬性（`tank`、`frst`、`pgbelly`…，>0＝在衣服裡）＋材質節點鏈（`toon(alt=…)` 再疊 `add_layer`，每層「屬性>0 換色」）。
     身體面另有區域：材質 0＝皮膚（上衣塗色）、1＝鈦甲緊身衣底下、2＝褲子底下（`hero_proto.py` 約 261 行）。
   - 做法：**身體只留一份網格＋每系列烘兩張貼圖**（上衣一張、下身一張），App 換貼圖就換裝，網格不動、不會穿模。
     1. 每個系列各跑一次 hero_proto（`TOP=X BOTTOM=X`，靜止姿勢即可，可並行）。身體網格拓撲各次相同（先比對頂點數，不同就報錯）。
     2. 身體展一次 UV（Smart UV Project，留邊距），算好「每個像素 → 三角形＋重心座標」對照表（外圍往外補 8 px 防接縫）。
        每個系列：把材質節點鏈解析成「底色＋[(屬性, 顏色, 暗面倍率)…]」，屬性用重心座標內插到像素再判斷 >0，
        直接得到每個像素的顏色。RGB＝亮面色，A＝暗面倍率（0＝不蓋，露出皮膚）。上衣圖只填區域 0、1 的面，下身圖只填區域 2。
        不用 Cycles 烘（ShaderToRGB 不支援），用 Blender 內建 numpy 算。先 1024²，邊緣太糊再升 2048²。
     3. 衣服網格另外匯出、跟身體同一副骨架：短褲 `bottom_short`、長褲 `bottom_long`、鈦甲緊身衣 `top_suit`，各自展 UV、每系列一張貼圖。
        各系列的剛性小零件（冰霜胸章等）照舊是 `top_<系列>`、`bottom_<系列>` 零件。
        從別次建模取來的網格，Armature 改指向基準那次的 rig（骨頭名稱、靜止姿勢相同）。
     4. `Toon.metal`：身體材質先讀上衣圖，A>0 就用它，否則讀下身圖，再沒有就用皮膚色；明暗照舊（ndl → 亮面／暗面＝色×A）。
        上衣圖放 `custom.texture`，下身圖放 baseColor 貼圖欄（unlit 不用它）。貼圖用 `TextureResource`、semantic `.raw`（避免 sRGB 轉換弄錯，顏色在 Python 先轉好）。
     5. `hero3d.json` 加 `outfits: {top: {系列: 貼圖檔, mesh?}, bottom: {系列: 貼圖檔, mesh: short|long}}`；測試頁加「上衣」「下身」兩個選單，可混搭。
     6. 接地高度（`low`）也要有 `bottom_short`、`bottom_long`、`top_suit` 各自一份。
   - 檢查：灰階也認得出（美術規定）；混搭時腰部（z 0.95～1.05）不露縫；USDZ＋貼圖總大小記下來（每張 PNG 色塊多，預期 < 200 KB）。

## 省用量的做法
- 一次做多個（動作一批 5～8 個、裝備一次 2～3 系列），每批只出一張低解析度總覽圖。
- 有範本之後（鈦甲、伏地挺身、下拉），照範本量產可以考慮用 Sonnet；新系列的造型方向和最後檢查用 Opus。

## App 端（Hero3DLab.swift）已知事項（2026-11-24）
- RealityKit 讀 hero3d.usdz 時，綁同一副骨架的網格會合併成**一個實體**，67 個零件變成 mesh 裡的 part（id＝零件名，如 `head_titan__ol`）。
  所以換裝、材質都在 part 層做：換裝＝篩 part 後用 `MeshResource.generate(from:)` 重組。0.36.2 起零件 67/67、骨頭 15/15 都對上。
- **著色**：CustomMaterial 用 `.unlit` 時只吃 **emissive**，寫 base color 會全黑（0.36.3 手機驗證）。
  `Toon.metal` 的 toonSurface／flatSurface 一律 `set_emissive_color`，base color 設 0。
